# Scaling of the AKS-ring fold attack

Cost measured in fold coefficients inspected, versus `p = spf(n)`.

### Why the fold leaks at all

For a prime `p` with `p^v || n` and `s = n / p^v`, Frobenius gives `(x+a)^n = (x^(p^v) + a)^s (mod p)`, so the folded coefficient

```
S_j  =  sum over { i : i*p^v = j (mod r) } of C(s, i) * a^(s-i)   (mod p)
```

`gcd(S_j, n)` is a non-trivial factor exactly when that progression sum vanishes mod `p`. Nothing forces it to; it behaves like a uniform residue, so each coefficient is a **~1/p** lottery ticket. Expected tickets needed: `Theta(p)`.

Median *coefficients / p* over the 16 solved cases: **0.87**, range 0.02 to 3.07, with **no trend in `p`** across three orders of magnitude. The spread is what a geometric process with success rate `1/p` predicts: the cost is a coin-flip count, not a smooth function.

2 run(s) exhausted the `r <= 400` budget without a hit. That budget is only about `2.5 * p` coefficients at the largest size tested, and a geometric process with rate `1/p` fails to fire within `2.5p` draws about `e^-2.5 = 8%` of the time -- so these are misses of the budget, not evidence against the model.

Either way the conclusion is the same: the fold attack costs `Theta(p)` coefficient evaluations -- the same wall as trial division, reached by a more expensive route.

### The barrier, stated plainly

Modulo a prime factor `p`, the AKS object *is* `(x^(p^v) + a)^(n/p^v)`. Its first non-trivial structure lives at degree `p^v`. Truncating below that degree sees nothing (Theorem 2); folding below that degree smears it across all `r` classes and each class keeps only a `1/p` chance of collapsing. Either way you pay `Theta(p)`.
