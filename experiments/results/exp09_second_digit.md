# The second n-adic digit, and what its hardness implies

`C(n,k) = n*m` for `gcd(k,n) = 1`.  How often does `gcd(m, n)` split `n`?

### The reduction

From `k*C(n,k) = n*C(n-1,k-1)` and `C(n,k) = n*m` we get `m = C(n-1,k-1)/k`. Since `gcd(k,n) = 1`, `k` is invertible, so for a prime `p | n`

```
m = 0 (mod p)   <=>   C(n-1, k-1) = 0 (mod p)
                <=>   some base-p digit of k-1 exceeds that of n-1   [Lucas]
```

`gcd(m mod n, n)` is a proper factor exactly when that digit condition holds for some prime factors of `n` but not all.

### The Lucas shortcut is exact

Checked **627** positions against exact `C(n,k) mod n^2`: **0** mismatches.

Sample sizes shrink as `p` grows for a reason worth noting: measuring the rate needs Lucas at *random* base-`p` digits, and one digit binomial `C(a,b) mod p` with `b ~ p/2` costs `O(p)` modular operations. Even *observing* this event is priced at the barrier.

The hit rate is **constant in `p`** -- it depends on the base-`p` digit profile of `n-1`, not on the size of `p`. Every other route in this project produced a `1/p` rate; this one is orders of magnitude above it and does not decay.

### What this means

**Proposition.** If `C(n,k) mod n^2` can be computed in `poly(log n)` for uniform random `k`, then `n = pq` can be factored in `O(1)` expected iterations. So that computation is factoring-hard.

This is where the project's barrier finally becomes *sharp*. Theorem 5 gives genuine random access to `C(n,k) mod n` -- for `n` of any size, in microseconds -- because the closed form only ever needs `C(n-1,k-1)` modulo the **small** number `k`, where Lucas and Granville apply. Extending that access by a single n-adic digit, to modulus `n^2`, would break factoring.

Two consequences worth stating:

1. The requirement, in Granville-style algorithms, that the modulus be *factored* before binomials can be reduced modulo it is essential -- not an artifact of how those algorithms are written.
2. The reason this project stalls is not that the Pascal row hides the factors. It does not: the factors are sitting in the second n-adic digit at constant density. The obstruction is purely that reading that digit is the same problem as factoring.
